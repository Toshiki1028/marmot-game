## 1. 目的・前提

本資料は、ゲームの想定プレイヤーを具体化し、操作方法・画面設計・対戦モード・演出の優先順位を決めるためのもの。

**注意：以下の人物・年齢・生活状況・行動は企画検討用の架空の設定であり、アンケートや実ユーザー調査で確認した事実ではない。** 市場調査で確認したのは、マーモット動画の視聴実績と、近い要素を持つ既存ゲームの存在である。ゲーム需要や年齢構成は未検証。

## 2. メインペルソナ：対戦アクション好き

| 項目 | 設定（仮説） |
| --- | --- |
| 名前 | 佐々木 悠（仮名） |
| 年齢・属性 | 24歳・社会人 |
| ゲーム環境 | 自宅のWindows PC、マウスとキーボード、ブラウザ |
| ゲーム経験 | アクション・対戦ゲームを継続的に遊ぶ。短時間でも勝敗が決まるゲームを好む |
| プレイ状況 | 帰宅後に一人でCPU戦、友人が来たときに同じPCで対戦 |
| 好むこと | 相手の動きを見て回避すること、攻守の切り替え、練習による上達 |
| 困りごと | 起動・設定が複雑なゲームは試すまでのハードルが高い。単純な連打だけの勝負は飽きやすい |
| 求める価値 | すぐ始められること、操作が理解しやすいこと、短い試合でも読み合いが成立すること |

### 想定する発言

> 「操作は簡単だけど、相手のパンチを読んで避けたり、食べるタイミングを選んだりできると面白い。」

### 想定プレイシーン

1. 紹介ページから「遊ぶ」を押す。
2. 初回に操作説明を確認し、CPU戦を始める。
3. 左右パンチ・回避、食事・座り食いの使い分けを覚える。
4. 1試合が終わったら、結果を見て再戦する。
5. 友人にゲームを見せ、マウス担当とキーボード担当に分かれてローカル対戦する。

### 設計への反映

- タイトル画面から少ない操作でCPU戦を開始できるようにする。
- 攻撃・回避・食事の状態が、キャラクターのポーズで伝わるようにする。
- 現在のにんじん所有者、各自の累積食事量、スタミナ、咆哮使用可否を見やすくする。
- CPU戦から2P戦への切り替えをわかりやすくする。
- 入力遅延が気になるパンチ・回避は、動作とヒット／成功の反応を明確にする。

## 3. サブペルソナ：動物の見た目・動きが好き

| 項目 | 設定（仮説） |
| --- | --- |
| 名前 | 高橋 美咲（仮名） |
| 年齢・属性 | 27歳・社会人 |
| ゲーム環境 | 主にPCブラウザ。ゲーム専用機器は使わないこともある |
| 関心 | マーモットなど動物の食事風景、表情、自然な仕草を見て楽しむ |
| ゲーム経験 | 日常的に対戦ゲームを遊ぶとは限らない。気になったブラウザゲームを試す程度 |
| プレイ状況 | SNSや友人の紹介で作品を知り、気軽に試す |
| 好むこと | 実物らしい丸みのある体形、瞬き、食事、驚き、咆哮などの動き |
| 困りごと | 対戦ルールが複雑だと始めにくい。キャラクターが極端にデフォルメされると期待と違う |
| 求める価値 | インストールせずに楽しめること、見ているだけでも面白い動物表現、基本操作を迷わないこと |

### 想定する発言

> 「マーモットらしい仕草がかわいい。ゲームが得意じゃなくても、すぐ遊べるといいな。」

### 想定プレイシーン

1. マーモットの見た目や紹介画像をきっかけに作品を開く。
2. 画面内の操作ガイドで遊び方を知る。
3. まずCPUと対戦し、瞬き・食事・回避・咆哮の演出を楽しむ。
4. 気に入ったら友人に紹介して一緒に2P対戦する。

### 設計への反映

- キャラクターはリアル寄りの体形・毛並み・仕草を優先する。
- ただし対戦時の動きやリアクションは見て分かる範囲でコミカルに演出する。
- 「にんじんを半分より多く食べた方が勝ち」というルールを開始前に簡潔に示す。
- 最初からすべての細かいルールを読ませず、操作説明を短く分ける。
- 不必要なインストールやアカウント登録を求めない。

## 4. 2人に共通するユーザーニーズ

| ニーズ（仮説） | 対応するゲームの仕様・UI |
| --- | --- |
| すぐ始めたい | GitHub Pages上で起動できるブラウザゲーム、簡潔なタイトル画面 |
| 操作を直感的に知りたい | CPU戦はマウス操作、2P戦はマウスとキーボードを分担。操作ガイドを表示 |
| 勝敗が分かりやすい | 巨大にんじんを先に50%超食べると勝利。双方の累積食事量を表示 |
| 攻守の読み合いを楽しみたい | 所有者は食事と回避、非所有者はパンチと睡眠。3回被弾で所有権交代 |
| キャラクターに愛着を持ちたい | リアル寄りのマーモットと、瞬き・座り食い・驚き・咆哮などの演出 |
| 友人と遊びたい | 同じPCでのローカル2P対戦（オンライン対戦は対象外） |

## 5. 企画への示唆・優先順位

1. **最優先：** パンチ・回避・食事・所有権交代・勝敗判定が、初回プレイでも理解できること。
2. **次点：** CPU戦とローカル2P戦を分かりやすく選択できること。
3. **演出面：** マーモットのリアルな見た目を保ちつつ、攻撃・回避・食事の動作が判別できること。
4. **追加要素：** 咆哮・共鳴の競り合い・疲労演出は、基本対戦を完成させてから調整する。

## 6. 仮説を検証するテスト項目

試作品の完成後、可能であれば両タイプに近いプレイヤーに試遊してもらう。

- 説明なし、または短い説明だけで操作を理解できるか。
- 初めて見た人が「どちらが食べているか」「あとどれくらいで勝つか」を判断できるか。
- 左右パンチ・回避の入力が直感的か。マウス側とキーボード側で有利不利を感じないか。
- 座り食い・睡眠・咆哮の違いがわかるか。
- マーモットらしい見た目や動きが魅力として伝わるか。
- もう一度プレイしたいか、友人と遊びたいか。

結果は「観察した事実」と「改善案」に分けて記録し、ペルソナやUI設計に反映する。

## 7. 次工程への引き継ぎ

- **サイトマップ：** タイトル／モード選択／操作説明／対戦／結果を基本画面候補とする。
- **ワイヤーフレーム：** にんじんの食事量、スタミナ、咆哮の残回数、プレイヤー別の操作をどう見せるか検討する。
- **デザインガイドライン：** リアル寄りのマーモットと、読みやすい対戦UIを両立する。
